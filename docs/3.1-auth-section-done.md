## Naprawione problemy

- [x] Jeden spójny mechanizm JWT dla wszystkich ról — usunięty fake
      `secrets.token_hex()` dla nie-adminów, wszyscy dostają prawdziwy JWT
- [x] Role: dwie, `admin` i `guest` (`Users.type`, domyślnie `guest`).
      `JWTAuthenticationMiddleware` **nie ufa roli z tokena** — po zdekodowaniu
      JWT dociąga usera z bazy przez `one_by_id_psql` i sprawdza `user.type`
      na żywo, więc zmiana roli/usunięcie usera działa natychmiast, nie
      dopiero po wygaśnięciu tokena. `Depends(JWTAuthenticationMiddleware(roles=["admin"]))`
      gotowe do użycia w 3.2-3.5.
- [x] `jwt.decode(..., algorithms=[...])` jako lista — już naprawione w pkt. 3
- [x] Sesja DB przez `Depends(get_db)` — koniec z globalną `db = SessionLocal()`
- [x] bcrypt bezpośrednio (nie passlib) — reużyte z pkt. 3
- [x] Wszystkie funkcje w handlerach i `_psql` mają `try/except` (konwencja
      przypomniana w trakcie tej sekcji — pilnować też w 3.2-3.5)
- [ ] Rewokacja tokenów — **świadomie NIE zaimplementowana** (jak w starym
      kodzie — refresh token weryfikowany tylko podpisem, bez sprawdzania w
      DB). Zostaje jako możliwe rozszerzenie na później, nie blokuje 3.1.

## Przy okazji: `DATABASE_URL` i infra

- `database/psql/database.py` — `DATABASE_URL` teraz przez `sqlalchemy.URL.create(...)`
  zamiast f-stringa (bezpieczniejsze wobec znaków specjalnych w haśle),
  `engine` z tuningiem poola (`pool_size=20, max_overflow=10, pool_timeout=30`)
- **Postgres wyleciał z Dockera całkowicie** — masz natywnego lokalnie i
  będziesz mieć natywnego na VPS. Usunięte: `infra/compose/local.docker-compose.yaml`,
  serwis `postgres` z `infra/compose/production.swarm.docker-compose.yaml`
  (backend łączy się teraz przez `host.docker.internal`, wymaga
  `ARTURSCIBOR_BACKEND_DB_HOST=host.docker.internal` w Dopplerze na prod),
  `docker_up`/`docker_down` z Makefile, zbędna sieć `backend_production`
  z `infra/ansible/tasks/networks.yml`

## Do odpalenia przez Ciebie

Migracja jest napisana i zweryfikowana w trybie offline (`alembic upgrade
head --sql` generuje poprawny SQL), ale nieodpalona przeciwko żywej bazie —
to już po Twojej stronie:

```bash
sudo -u postgres psql -c "CREATE ROLE arturscibor WITH LOGIN PASSWORD 'arturscibor_dev';"
sudo -u postgres psql -c "CREATE DATABASE arturscibor_portfolio OWNER arturscibor;"
uv run alembic upgrade head
```

`env/local.env` już ustawiony pod te dane (`ARTURSCIBOR_BACKEND_DB_USER=arturscibor`,
`ARTURSCIBOR_BACKEND_DB_PASSWORD=arturscibor_dev`).
